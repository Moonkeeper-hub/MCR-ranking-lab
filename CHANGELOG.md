## Changelog

## v0.31

- Добавлена третья вкладка **Mock generator** для воспроизводимого создания синтетических рейтинговых данных.
- Реализован генератор пула игроков (`players.csv`):
  - редактируемое базовое имя;
  - скрытая сила `latent_elo`;
  - вероятность участия во внутренних турнирах;
  - вероятность участия во внешних турнирах;
  - стабильность результатов;
  - изменение силы со временем (`skill_drift_per_year`);
  - `active_from` и `active_to`;
  - `include_in_rating`;
  - страна / метка профиля;
  - начальные поля MCR;
  - множитель экземпляров шаблона;
  - автоматическое добавление характеристик к имени.
- Добавлена таблица созданных player templates с редактированием, дублированием и удалением.
- Реализован генератор шаблонов турниров:
  - условное название;
  - целевой и минимальный размер;
  - тип рассадки `Random`, `Swiss`, `Seeded → Swiss`;
  - число туров / ханчанов;
  - внутренний или внешний турнир;
  - статусный признак;
  - рейтинговая квота;
  - метод расчёта рейтинга для квоты;
  - число игроков замены;
  - политика силы замен;
  - периодичность / число турниров в год;
  - фиксированные месяцы;
  - влияние skill;
  - tournament randomness;
  - множитель шаблона.
- Добавлена таблица tournament templates с редактированием, дублированием и удалением.
- Для квотного отбора добавлен **Neutral mock rating**, не зависящий от исследуемых рейтинговых методик:
  - результат турнира нормируется в диапазон `0–1000`;
  - внутренний mock-рейтинг обновляется экспоненциальным сглаживанием;
  - параметр `α` доступен в расширенных настройках.
- В качестве альтернативы для квотного отбора можно использовать `MCR-2026 default`, `RR default`, `TrueSkill Tournament default` или `Elo-PL default`.
- Добавлен воспроизводимый history generator с глобальным `seed`, начальной и конечной датой истории.
- История строится последовательно:
  - шаблоны турниров разворачиваются в конкретные события;
  - для каждого события определяется eligible pool;
  - учитываются `active_from` и `active_to`;
  - резервируются места игроков замены;
  - применяется рейтинговая квота;
  - заполняются остальные места;
  - проводится турнир по отдельным турам;
  - присваиваются итоговые `place`.
- После `active_to` игрок больше не участвует в новых турнирах, но остаётся в `players.csv` и в историческом рейтинговом состоянии.
- Игрок до `active_from` не может участвовать в турнире и не участвует в формировании квот до своего появления.
- Для **external tournament** состав формируется по отдельному правилу:
  - игроки `include_in_rating=true` могут попасть только через рейтинговую квоту;
  - остальные регулярные места заполняются случайными игроками `include_in_rating=false`;
  - если внешних игроков недостаточно, свободные места заполняются одноразовыми substitute players.
- Игроки замены резервируют места **до** отбора обычных участников, поэтому их заданное количество гарантированно сохраняется в сгенерированном турнире.
- Одноразовые substitutes автоматически добавляются в generated `players.csv` с `include_in_rating=false`, `is_substitute=true` в соответствующем результате и сроком активности в пределах конкретного турнира.
- Турниры симулируются по отдельным турам:
  - формируется рассадка;
  - для каждого стола генерируется performance на основе `latent_elo`, drift, consistency и tournament randomness;
  - начисляются tournament points `4 / 2 / 1 / 0`;
  - после каждого тура обновляется standings;
  - `Swiss` группирует игроков по текущему результату;
  - `Seeded → Swiss` использует первоначальный посев, затем переходит к Swiss.
- Итоговое место определяется по:
  1. tournament points;
  2. суммарному raw performance;
  3. среднему месту за столами;
  4. детерминированному tie-break.
- Добавлен `manifest.json`, содержащий seed, период истории, параметры генератора и использованные шаблоны.
- После генерации доступны:
  - `Use in Rating Lab`;
  - экспорт `players.csv`;
  - экспорт `results.csv`;
  - экспорт `manifest.json`.
- `Use in Rating Lab` передаёт синтетический dataset непосредственно в Comparison без повторного импорта файлов.
- Рейтинговые движки MCR-2026, RR, TrueSkill Tournament и Elo-PL не изменялись.

## v0.30

- Добавлены две альтернативные рейтинговые методики, основанные на итоговых местах игроков в турнирах:
  - **TrueSkill Tournament**;
  - **Elo-PL**.
- Обе методики интегрированы в:
  - Laboratory;
  - Comparison;
  - историческую шкалу;
  - пользовательские presets;
  - метрику дистанции;
  - worker/cache pipeline.
- **TrueSkill Tournament** трактует весь турнир как одно многопользовательское наблюдение по полному порядку итоговых мест.
- Для TrueSkill используются канонические состояния `μ` и `σ`; ранжирование выполняется по conservative score `μ - kσ`.
- Добавлены редактируемые коэффициенты для:
  - стартового `μ`;
  - стартового `σ`;
  - `β`;
  - `τ`;
  - `k`;
  - общей турнирной поправки;
  - влияния числа участников;
  - влияния числа туров / ханчанов.
- Реализован календарный `τ/decay`: неопределённость игрока увеличивается в зависимости от времени с его предыдущего турнира; множитель decay можно изменять от `0` до `3`.
- Реализована редактируемая турнирная поправка TrueSkill с отдельными коэффициентами для размера турнира и его дистанции.
- Формула TrueSkill отображается через KaTeX и является интерактивной: по клику на параметр открывается его объяснение и соответствующий control.
- **Elo-PL** реализует полноценную модель Plackett–Luce по полному порядку мест, а не pairwise-разложение.
- Стартовый рейтинг Elo-PL — `1500`.
- В лаборатории Elo-PL доступны:
  - `Base K`;
  - PL scale / temperature;
  - влияние размера турнира;
  - влияние опыта игрока;
  - влияние числа ханчанов;
  - параметры снижения experience bonus;
  - минимальное число игроков;
  - нормализация отображаемого рейтинга.
- Нормализация Elo-PL изменяет только представление (`Off`, `0–1000`, `0–3000`) и не меняет внутреннее состояние модели.
- Формула Elo-PL также отображается через KaTeX с интерактивными пояснениями параметров.
- Добавлена нативная реализация TrueSkill без `ts-trueskill` и `mathjs`.
- Удалены транзитивные High-severity уязвимости, связанные с `mathjs`.
- TrueSkill-ядро теперь находится в собственном TypeScript-модуле проекта и не требует внешней runtime-библиотеки.
- Исправлен KaTeX-рендер формулы TrueSkill после перехода на нативную реализацию.

## v0.29

- Реализована **метрика дистанции** для сравнения рейтинговых методик.
- Для каждого игрока и каждой методики анализируется дистанция в турнирах до достижения и повторного подтверждения лучшего места.
- Учитываются:
  - начальный полный горизонт устаревания;
  - повторные достижения того же или более высокого места;
  - последний незавершённый интервал до конца истории.
- Добавлены настройки:
  - `Top-N`;
  - шаг диапазона мест от `1` до `10`.
- Для каждой методики строится пара гистограмм:
  - среднее число турниров на наблюдение;
  - нормированное число турниров относительно общего числа зачётных турниров методики.
- Для сравниваемых графиков используется единая шкала Y.
- Для метрики доступны:
  - CSV-экспорт;
  - SVG-экспорт.
- Расчёт метрики вынесен в отдельный модуль `src/analysis/rankingDistance.ts`.
- Добавлен performance layer:
  - memoization итоговых расчётов;
  - кеширование истории;
  - dataset/config cache keys;
  - повторное использование уже рассчитанных snapshots;
  - исключение лишних пересчётов при сортировке, поиске, выборе игрока, изменении периода и настройках визуализации.
- Добавлен второй performance layer:
  - фиксированный пул из **2 Web Workers**;
  - две независимые FIFO-очереди вычислений;
  - dataset передаётся каждому worker только один раз;
  - MCR/RR и другие независимые методики могут считаться параллельно;
  - UI больше не блокируется на время тяжёлых расчётов.
- Добавлен debounce `350 ms` для рейтинговых controls:
  - движение slider больше не запускает расчёт на каждом `input`;
  - серия клавиатурных изменений объединяется в один пересчёт;
  - расчёт запускается после прекращения изменения параметра.
- Добавлена защита от устаревших async-результатов через `runId`.
- Повторный запрос идентичной конфигурации использует уже выполняющийся Promise или готовый cache entry.
- Ограничено хранение расчётов в LRU-кеше.
- Worker history возвращает только данные, необходимые интерфейсу, чтобы не раздувать память полными копиями внутренних результатов.
- Математика существующих рейтинговых движков при performance-оптимизации не изменялась.

## v0.28

- Добавлен второй полноценный рейтинговый движок — **RR (внутренний российский рейтинг по риичи)**.
- Формула RR перенесена с Python на TypeScript и работает полностью в браузере на тех же `players.csv` и `results.csv`, что и MCR-2026.
- Реализованы обе части RR:
  - первая часть с выбором лучших турниров и правилом `5 + 80%` дополнительных результатов;
  - вторая часть по четырём лучшим турнирам и общему знаменателю из четырёх максимальных коэффициентов турниров.
- Реализованы:
  - базовый ранг игрока `0–1000`;
  - коэффициент количества игроков;
  - коэффициент количества ханчанов;
  - двухлетнее устаревание результатов;
  - минимальное количество турниров для попадания в рейтинг.
- Добавлены исторические `HARDCODED_COEFFICIENTS` для турниров с отсечением. Коэффициенты применяются к конкретным парам `tournament_id + player_id` и доступны для редактирования в лаборатории.
- Добавлена интерактивная формула RR в KaTeX. Нажатие на обозначения и коэффициенты открывает пояснение и связанные настройки.
- Все основные параметры RR стали редактируемыми:
  - веса двух частей рейтинга;
  - количество учитываемых турниров;
  - доля дополнительных результатов;
  - количество лучших турниров второй части;
  - коэффициенты и диапазоны количества игроков;
  - коэффициенты и диапазоны количества ханчанов;
  - параметры устаревания;
  - специальные коэффициенты турниров с отсечением.
- Перестроена архитектура интерфейса:
  - основной режим — **«Сравнение методик + история»**;
  - отдельная **«Лаборатория»** для настройки MCR-2026 и RR.
- В лаборатории можно выбрать методику `MCR-2026` или `RR`, изменить её параметры и сохранить пользовательский preset.
- Пользовательские presets сохраняются локально в браузере и могут использоваться как отдельные методики для сравнения.
- Сравнение методик больше не зависит от текущих несохранённых настроек лаборатории.
- Добавлена независимая валидация данных для каждого рейтингового движка:
  - ошибка MCR-2026 больше не блокирует расчёт RR;
  - методики могут обработать разное количество турниров из одного dataset.
- Для MCR-2026 добавлены режимы обработки значения `ЧУТ`, отсутствующего в нормативной таблице:
  - strict;
  - ближайшее нижнее значение;
  - ближайшее значение;
  - линейная интерполяция;
  - исключение турнира.
- Канонический `MCR-2026 default` использует strict-режим и явно показывает неполный расчёт, если часть турниров нельзя обработать нормативно.
- Для RR добавлена собственная проверка турнирных требований, которые можно определить из CSV.
- Историческая шкала теперь позволяет выбрать любые две методики:
  - `MCR-2026 default`;
  - `RR default`;
  - пользовательские MCR presets;
  - пользовательские RR presets.
- Карточки `Методы` и `Период` стали интерактивными:
  - можно заменить пару сравниваемых методик;
  - можно ограничить исторический диапазон дат.
- График движения игрока показывает две выбранные методики одновременно.
- Таблица **«Рейтинг после этого шага»** теперь сравнивает выбранные Метод 1 и Метод 2 вместо прежней схемы «экспериментальный / эталон».
- `Δ Rating` и `Δ место` рассчитываются относительно выбранной пары методик.
- В верхней таблице сравнения и в таблице рейтинга после выбранного шага добавлены:
  - сортировка по колонкам;
  - отдельный CSV-экспорт.
- Подготовлена архитектурная база для следующего этапа — общей метрики дистанции и графического сравнения методик.

## v0.27

- Уточнена модель внешних игроков для MCR-2026.
- Добавлен признак `include_in_rating`.
- Внешние игроки могут участвовать в турнирах и полностью обсчитываться движком, но не отображаться во внутреннем рейтинге.
- «Утки» теперь:
  - получают собственные EU и даны;
  - сохраняют своё рейтинговое состояние между турнирами;
  - участвуют в расчёте `KT_EU` при повторном появлении;
  - не участвуют в итоговом внутреннем рейтинге;
  - не участвуют в квотном отборе внутренних игроков на внешние турниры.
- Новые внешние игроки начинают с `EU = 0`.
- Добавлен переключатель **«Из кю максимум до 1 дана за один турнир»**.
- Добавлена колонка **«Турниров»** в основную и историческую таблицы.
- Обновлён mock dataset для исследования поведения MCR-2026:
  - 10-летняя история;
  - внутренние и внешние турниры;
  - группы игроков: чайки, курочки, голуби, хамелеоны и утки;
  - устойчивые `player_id` для возвращающихся внешних игроков;
  - реалистичнее распределены размеры внутренних турниров;
  - половина внутренних турниров генерируется с небольшими размерами `12 / 16 / 20`.
- Добавлены характеристики активности:
  - `rare`;
  - `medium`;
  - `frequent`.
- Характеристика активности включена непосредственно в синтетические имена игроков: «Редкий», «Средний», «Частый».
- Встроенный `Demo dataset` приведён к той же структуре, что и рабочие mock CSV для экспериментов.
- Продолжена очистка MCR-2026 от legacy-неоднозначностей и подготовка данных к сравнению альтернативных методик.

- `KT_ЧУТ` переведён на строгий lookup по нормативной таблице без интерполяции.
- Сохранено округление `KT_EU` вниз с шагом `0.05`.
- `KT_W` переосмыслен как бонус статусного турнира.
- Исправлено взаимное погашение плюсов и минусов у дановых игроков.
- Изменён порядок временного понижения: проверка выполняется при обработке турнира только для игроков, не участвующих в нём.
- Убрано календарное изменение EU между турнирами без события расчёта.
- `initial_dan_date` теперь трактуется как дата последнего турнира, на котором выполнено `EU_before <= NR × KT`.

  - `Нет`;

- Добавлены три политики EU игроков замены:
  - `EU = 0`;
  - `среднее арифметическое`;
  - `считать новичком`.
- Добавлено поле `is_substitute`.
- `is_status_tournament` заменяет прежнюю семантику `is_world_europe`; старое поле временно поддерживается как alias.
- Demo dataset перестроен под MCR-2026:
  - 120 синтетических игроков;
  - 83 турнира;
  - только допустимые значения ЧУТ;
  - количество результатов каждого турнира соответствует ЧУТ;
  - добавлены игроки замены;
  - добавлены статусные турниры;
  - для импортированных дановых игроков задана предыстория через `initial_dan_date`.
