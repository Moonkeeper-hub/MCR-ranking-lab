# MCR описанный

Реализация **Приложения 2 v0.8** с уточнением Виталия от **17.11.2026**. Методика заменяет Legacy MCR observed; это реализация описанных правил, а не реконструкция опубликованных рейтингов.

Источники:

- [Приложение 2 v0.8](sources/appendix-2-v0.8.pdf).
- [Двойной пересчёт, комментарий от 17.11.2026](sources/double-recalculation-2026-11-17.pdf).

Уточнение применяется к порядку двойного пересчёта и подготовке исходных ЭУ. Остальные правила берутся из Приложения 2. Отдельный «Проектный MCR (Приложение 3)» сохраняет свою методику.

## Итоговый рейтинг

```text
Rating = 0.25 × EU + 0.75 × T5
NR = 1000 × (N − place) / (N − 1)
T5 = Σ top-5(NR × KT₂ × VT) / 5
```

`EU` — итоговый эволюционный уровень после обработки турнира. Если результатов меньше пяти, знаменатель T5 всё равно равен пяти. Для каждого исторического результата используется окончательный KT₂ его турнира.

`N` / ЧУТ — максимальное число одновременно играющих участников в любой сессии, включая замены. CSV должен содержать это значение в `participants`; количество строк CSV не подменяет ЧУТ.

## Коэффициент турнира

```text
KT = 0.1 × sessions + KT_ЧУТ(N) + KT_EU + KT_W
KT_EU = floor((mean(EU без замен) / 1000) / 0.05) × 0.05
KT_W = 1 для статусного турнира, иначе 0
```

Замены исключаются **и из суммы, и из числа игроков** при усреднении EU. Они по-прежнему входят в ЧУТ и занимают места. Для вырожденного состава без обычных игроков компонент среднего EU принимается равным нулю.

## Двойной пересчёт

На каждом турнире:

1. Проверить просрочку всех учитываемых игроков, **включая участников текущего турнира**. Получить исходные состояния `EU₀` и отметки после временного понижения. Новым и неизвестным зарубежным игрокам задать `EU=0`, 12 кю; замены имеют неизменяемый `EU=0`.
2. По `EU₀` состава вычислить `KT₁`.
3. На копиях исходных состояний рассчитать промежуточные `EU₁` **всех участников**, включая уже известных. Используются обычные правила рангов и отметок.
4. По `EU₁` состава вычислить `KT₂`.
5. Отбросить промежуточные состояния. От исходных `EU₀` и исходных отметок выполнить один окончательный расчёт по `KT₂`.

```text
states₀ = expiry(previous states, tournament date)
KT₁ = coefficient(states₀)
states₁ = evolve(copy(states₀), KT₁)
KT₂ = coefficient(states₁)
final states = evolve(states₀, KT₂)
```

Первый проход не даёт второго набора плюсов: его состояния нужны только для KT₂. Итоговый расчёт не продолжается от EU₁. Различать «настоящих новичков» и уже существующих q12 для области двойного пересчёта в нормативном default не требуется.

В лабораторных терминах это `doubleStrikeMode=A`, `doubleStrikeScope=every_tournament`.

## Ранги и отметки

Кю-шкала EU: `0, 50, 100, 150, 200, 250, 500, 750, 1000, 1250, 1500, 1750` соответствует рангам от 12 кю до 1 кю. Дан-шкала: от `2000` (D1) до `7500` (D12), шаг `500`.

Обозначим `P = NR × KT` для соответствующего прохода.

- Если `P < EU_before`, ранг и отметки не меняются. Плохое выступление само по себе не даёт минус.
- Кю при `P < 2000` получает ближайший снизу EU кю-шкалы, если условие `P ≥ EU_before` выполнено.
- Кю при `P ≥ 2000` сначала получает D1/EU=2000 и затем `floor((P−2000)/500)` плюсов. Пример: `P=2640` → D1+; `P=3000` → D2.
- Дановый игрок при `P ≥ EU_before` получает `floor((P−EU_before)/500)` плюсов.
- Плюсы и минусы взаимно уничтожаются. Два плюса обмениваются на следующий дан; число плюсов за турнир не ограничено. Верхний ранг таблицы — D12.
- Подтверждение без нового плюса **не снимает существующий минус**. Например, D4− при `3500 ≤ P < 4000` остаётся D4−; при `P=4000` один плюс погашает минус.

Условие `P ≥ EU_before` обновляет дату подтверждения даже при нуле новых плюсов. Промежуточная дата подтверждения первого прохода не сохраняется.

## Временное понижение

Дата подтверждения — дата последнего турнира, на котором выполнено условие `EU_before ≤ NR × KT`. Проверка выполняется перед расчётом очередного турнира для всех игроков, в том числе возвращающихся участников и отсутствующих игроков.

Первый минус начисляется при сроке **более 12 календарных месяцев** с подтверждения; последующие годовые рубежи — при достижении 24, 36 и т. д. месяцев. Каждый рубеж учитывается только один раз. Два минуса понижают ранг на один дан и сбрасывают отметки; D1 и ранги ниже не получают минусы и не понижаются.

Пример Виталия: D3− без нового подтверждения в течение 500 дней получает ещё один минус и входит в расчёт текущего турнира как D2. Это состояние участвует в KT₁ и является исходным для окончательного прохода.

Ранг меняется при обработке турниров, а не от одного изменения даты просмотра. Дата просмотра влияет на устаревание результатов T5.

### Импорт исходного состояния

- `initial_eu`, `initial_marks` задают исходный EU и отметки.
- `initial_dan_date` — дата последнего подтверждения до загруженной истории.
- Необязательное `initial_expiry_periods_applied` — число годовых рубежей после этой даты, уже учтённых в импортированном состоянии. Default `0`. Наличие минуса само по себе не означает, что первый рубеж после последнего подтверждения уже учтён: минус мог сохраниться при подтверждении без новых плюсов.

Для состояния D3− из примера с ещё не начисленным минусом за 500 дней используется `initial_expiry_periods_applied=0`. Если первый годовой минус уже включён в выгрузку, укажите `1`, чтобы не начислить его второй раз. После нового подтверждения счётчик сбрасывается.

В истории режим «Чистый старт» сбрасывает все начальные поля MCR, включая этот счётчик. Для продолжения импортированного состояния выберите «Игроки + импортированный EU».

## Внешние игроки и входные данные

`include_in_rating=false` скрывает игрока из итоговой внутренней таблицы, но не исключает его из состава и расчёта турнира. Если его история/начальный EU неизвестны, он начинает с EU=0.

Входные CSV предполагаются уже отобранными по аккредитации Федерацией: отдельного признака аккредитации в схеме нет. Правила полей: [DATA_FORMAT.md](DATA_FORMAT.md).

## Лаборатория и реализация

Сохраняются независимые настраиваемые веса EU/T5 (сумма 1), количество лучших результатов, коэффициент сессий, масштаб KT_ЧУТ, нормализатор/масштаб/округление KT_EU, статусный бонус, таблицы KT_ЧУТ и VT, параметры устаревания и эволюции рангов. Нулевой шаг округления отключает округление KT_EU.

Режимы без пересчёта, накопительный B, область «только новички», альтернативные политики замен и ограничение продвижения из кю — **лабораторные эксперименты**, не default Приложения 2. Замены исключаются из среднего EU в этой методике при любой лабораторной политике их EU.

Основной движок — `src/engine/legacy.ts`, default-профиль — `defaultDescribedMcrConfig()`, эволюция — `evolutionPolicy=appendix2_v08`. Эти же настройки используются в Web Worker, истории, сравнении и Prediction Benchmark. Проектный MCR продолжает использовать отдельный профиль `appendix3`.

Идентификатор новой методики — `mcr-described`, истории — `mcr-described-default`; CSV сравнения использует колонки `mcr_described_rank`, `mcr_described_rating`, `delta_described_minus_project`. Старые presets observed не применяются к новой методике автоматически; их исходное хранилище `mcr-rating-lab-presets-v1` сохраняется. Поддерживаемые presets остальных методов читаются из него до первого сохранения в новое хранилище v2.

Проверки нормативных сценариев: `npm test`. Production-сборка: `npm run build`.
