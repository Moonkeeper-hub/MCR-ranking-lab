# v0.29.2 — Performance II

Цель патча — убрать лишние пересчёты и вынести необходимые рейтинговые расчёты из UI thread без изменения математики MCR-2026, RR и метрики дистанции.

## Что изменено

- Фиксированный пул из **2 Web Workers**. У каждого worker собственная FIFO-очередь; новая задача отправляется в менее загруженную очередь.
- Dataset (`players` + `results`) передаётся каждому worker один раз после загрузки CSV. Последующие задачи передают только методику, конфигурацию и дату расчёта.
- При замене dataset оба worker пересоздаются, а задачи старого dataset отменяются.
- Cold calculations MCR/RR выполняются в workers; cache hit возвращается без нового расчёта.
- Исторические расчёты MCR/RR также выполняются в workers. В main thread возвращается облегчённый snapshot: ranking + processedTournamentCount, без полного CalculationResult на каждом шаге.
- Сохраняется LRU-cache из v0.29.1 и deduplication одинаковых in-flight задач.
- Добавлен generation guard: результат устаревшего пересчёта не заменяет более новую конфигурацию.
- Для range-controls MCR и RR применяется debounce **350 ms**. Во время drag или серии нажатий стрелок обновляется значение control, но рейтинговый движок запускается один раз после паузы.
- Сортировка, выбор игрока, перемещение по уже рассчитанной истории, экспорт и изменение отображаемого периода не запускают рейтинговые движки заново.

## Не изменено

Файлы алгоритмов `legacy.ts`, `evolution.ts`, `rr.ts`, `simulation.ts` и `rankingDistance.ts` не изменялись относительно v0.29.1. Патч меняет только orchestration, scheduling, caching и threading.

## Память

В браузере находятся три копии нормализованного dataset: одна в main thread и по одной в каждом из двух workers. Число workers фиксировано и не растёт с количеством добавленных методик. Исторические snapshot-ы, возвращаемые из workers, облегчены, чтобы не дублировать полный объект результата для каждого турнира.
