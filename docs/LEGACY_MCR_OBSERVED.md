# Legacy MCR (Новиков observed)

Legacy MCR (Новиков observed) — экспериментальная реконструкция логики фактически публиковавшегося российского рейтинга MCR.

Методика оформлена как самостоятельный рейтинговый профиль. Она использует общую инфраструктуру MCR-движка: `NR`, `KT`, `VT`, `T5`, последовательную обработку турниров и состояние EU игрока.

Название `observed` принципиально: это не буквальная реализация текущего текста Приложения 3, а наиболее близкая к опубликованным рейтингам реконструкция наблюдаемого поведения. Отдельные правила могут уточняться по мере появления новых контрольных данных.

## Итоговый рейтинг

```text
Rating = 0.25 × EU + 0.75 × T5
```

## Норморейтинг

```text
NR = 1000 × (ЧУТ - место) / (ЧУТ - 1)
```

Турнирный performance игрока:

```text
performance = NR × KT
```

## Коэффициент турнира

```text
KT = KT_ЧС + KT_ЧУТ + KT_EU + KT_W
```

Компоненты `KT_ЧС`, `KT_ЧУТ`, `KT_EU` и `KT_W` рассчитываются тем же общим MCR-механизмом, что и остальные MCR-конфигурации.

### KT_EU

```text
KT_EU = mean(EU участников) / 1000
```

Результат округляется вниз с шагом `0.05`.

Для расчёта `KT_EU` используются состояния игроков на начало турнира, кроме специального промежуточного обновления настоящих новичков в режиме Fixed DS-A, описанного ниже.

### Игрок замены

Default observed-профиля:

```text
substitute EU = 0
```

Замена участвует в расчёте силы состава с этим EU, если иное явно не задано экспериментальной конфигурацией.

## T5

```text
T5 = Σ top-5(NR × KT × VT) / 5
```

Используется пять лучших взвешенных результатов. При меньшем числе результатов знаменатель остаётся равным 5.

## Изменение EU: кю

Для игрока, находящегося в кю, результат сначала сопоставляется со шкалой кю.

Если performance пересекает границу первого дана, observed-логика не позволяет выполнить прямой переход из кю сразу в D2/D3 и выше. Сначала устанавливается первый дан:

```text
kyu → D1
EU = 2000
```

После этого остаток performance выше `2000` не теряется. За каждые полные `500` пунктов превышения начисляется один плюс:

```text
successes = floor((performance - 2000) / 500)
```

Пример:

```text
q2, performance ≈ 2640
→ D1
→ floor((2640 - 2000) / 500) = 1 плюс
→ D1+
```

Таким образом, кю-игрок всегда входит в дановую шкалу через D1, но сильный результат может сразу дать D1+ и далее запустить обычную механику накопления плюсов.

## Изменение EU: даны

Успешным подтверждением считается результат, при котором:

```text
performance >= EU_before
```

Если у игрока до турнира имеется отрицательная отметка, успешное подтверждение сначала снимает этот минус:

```text
Dk- → Dk
```

Только после этого учитываются новые плюсы, заработанные тем же результатом.

Количество новых плюсов определяется превышением performance над текущим EU:

```text
successes = floor((performance - EU_before) / 500)
```

Два плюса переводят игрока на следующий дан согласно общей дановой механике.

Следствие observed-правила: игрок `D4-`, показавший performance не ниже `3500`, но ниже `4000`, становится `D4`, а не остаётся `D4-`.

## Double Strike: Fixed DS-A, newcomers only

Default observed-конфигурации:

```text
Mode: Fixed DS-A
Scope: newcomers_only
```

Наблюдаемое поведение отличается от накопительного двойного пересчёта всех участников. Первый проход не изменяет EU уже известных игроков и не является первой половиной кумулятивного повышения.

Алгоритм:

1. Зафиксировать состояния и EU всех уже известных игроков на начало турнира.
2. Настоящим новичкам задать стартовое состояние `q12 / EU = 0`.
3. По исходному составу вычислить первый коэффициент турнира `KT₁`.
4. По `KT₁` рассчитать промежуточные уровни **только настоящих новичков**.
5. Преобразовать их промежуточные результаты в дискретные EU шкалы кю/данов и подставить эти EU вместо стартового нуля.
6. Не изменяя EU остальных участников, пересчитать коэффициент турнира и получить `KT₂`.
7. От исходных предтурнирных состояний выполнить **один финальный расчёт всех участников** по `KT₂`.

Схематично:

```text
start states
    ↓
KT₁ from fixed pre-tournament EU
    ↓
provisional evolution of true newcomers only
    ↓
replace newcomers' EU=0 with their discrete provisional EU
    ↓
KT₂
    ↓
final evolution of ALL players from original start states
```

### Что означает «настоящий новичок»

Настоящий новичок — игрок, для которого до рассматриваемого турнира отсутствует известное рейтинговое состояние.

Игрок, уже присутствующий в базе или предыдущем состоянии даже как `q12 / EU = 0`, новичком для промежуточного прохода не считается.

Это различие существенно: существующий `q12` остаётся с фиксированным `EU = 0` при вычислении `KT₁` и `KT₂`, а изменение его уровня происходит только в финальном проходе вместе со всеми участниками.

### Чего Fixed DS-A не делает

Observed-профиль **не** выполняет следующие действия:

```text
не повышает EU старых игроков в первом проходе;
не использует их provisional-повышения для усиления KT;
не применяет к ним положительные изменения дважды;
не переносит результат первого прохода в финальное состояние старого игрока.
```

Именно это отличает Fixed DS-A от накопительного DS-B и от буквальной интерпретации двойного пересчёта по текущему Приложению 3.

## Новые игроки

Для настоящего нового игрока до первого турнира:

```text
initial_eu = 0
initial_marks = 0
initial_dan_date = empty
```

В турнире с Fixed DS-A его промежуточный уровень сначала определяется по `KT₁`, затем его дискретный EU участвует в расчёте `KT₂`, а итоговое состояние определяется заново по `KT₂`.

## Временное понижение

Неактивность обрабатывается последовательной симуляцией турниров.

`initial_dan_date` используется как исходная дата последнего подтверждения данового состояния до начала загружаемой истории.

## Внешние игроки

`include_in_rating=false` исключает игрока только из отображаемой внутренней рейтинговой таблицы.

Такой игрок продолжает участвовать в турнирном расчёте и может влиять на `KT` и результаты остальных участников.

## Default-конфигурация

```text
rating = 0.25 × EU + 0.75 × T5
T5 = top 5
KT_EU rounding = floor to 0.05
Double Strike = Fixed DS-A
Double Strike scope = newcomers_only
newcomer provisional EU = discrete level EU after KT₁
known players during DS provisional pass = fixed at pre-tournament EU
final pass = all players from original pre-tournament state using KT₂
substitute EU = 0
kyu→dan = through D1, residual excess → pluses
successful dan confirmation = clear existing minus first, then add new pluses
successes per dan step = 2
dan performance step = 500
```

## Статус реконструкции

Эта методика является исследовательской реконструкцией наблюдаемого Legacy MCR, а не утверждением о наличии полностью восстановленного оригинального алгоритма или исходной базы расчёта.

Fixed DS-A с областью `newcomers_only`, снятие минуса при успешном подтверждении и переход из кю через D1 введены потому, что они лучше согласуются с проверенными опубликованными состояниями рейтинга, чем буквальная реализация текущего Приложения 3.

При появлении новых контрольных данных observed-профиль может уточняться; такие уточнения должны вноситься отдельно от Project MCR (Приложение 3), чтобы не смешивать реконструкцию фактического Legacy-поведения и проектную нормативную методику.
