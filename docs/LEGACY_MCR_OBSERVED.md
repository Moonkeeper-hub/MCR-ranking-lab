# Legacy MCR (Новиков observed)

Legacy MCR (Новиков observed) — экспериментальная реконструкция логики фактически публиковавшегося российского рейтинга MCR.

Методика оформлена как самостоятельный рейтинговый профиль. Она использует общую инфраструктуру MCR-движка: `NR`, `KT`, `VT`, `T5`, последовательную обработку турниров и состояние EU игрока.

Название `observed` подчёркивает, что часть поведения восстановлена по наблюдаемым опубликованным результатам, а не по отдельному нормативному документу.

## Итоговый рейтинг

```text
Rating = 0.25 × EU + 0.75 × T5
```

## Норморейтинг

```text
NR = 1000 × (ЧУТ - место) / (ЧУТ - 1)
```

## Коэффициент турнира

```text
KT = KT_ЧС + KT_ЧУТ + KT_EU + KT_W
```

Компоненты `KT_ЧС`, `KT_ЧУТ`, `KT_EU` и `KT_W` рассчитываются тем же общим MCR-механизмом, что и остальные MCR-конфигурации.

### KT_EU

```text
KT_EU = mean(EU участников) / 1000
```

Результат округляется вниз с шагом `0.05`.

### Игрок замены

Default:

```text
substitute EU = 0
```

## T5

```text
T5 = Σ top-5(NR × KT × VT) / 5
```

Используется пять лучших взвешенных результатов. При меньшем числе результатов знаменатель остаётся равным 5.

## Изменение EU: кю

Игрок из кю сначала движется по шкале кю согласно достигнутому `NR × KT`.

Если performance пересекает границу первого дана, переход обрабатывается через D1:

```text
kyu → D1
```

После установления D1 остаток performance выше `EU = 2000` не теряется.

За каждые полные `500` пунктов превышения начисляется один плюс:

```text
successes =
floor((performance - 2000) / 500)
```

Таким образом переход из кю не выполняет прямой числовой прыжок в D2/D3, но достаточно высокий результат может сразу сформировать плюсы первого дана.

## Изменение EU: даны

Если результат подтверждает текущий дан:

```text
EU_before <= NR × KT
```

сначала подтверждается текущий уровень.

Если у игрока имеется минус, успешное подтверждение снимает его до начисления новых плюсов.

После этого превышение performance над текущим EU переводится в плюсы:

```text
successes =
floor((NR × KT - EU_before) / 500)
```

Два плюса переводят игрока на следующий дан.

## Подтверждение и минусы

Подтверждение трактуется как отдельное действие над состоянием игрока.

Для игрока с отрицательной отметкой:

```text
Dk- → подтверждённый Dk
```

После снятия минуса к подтверждённому состоянию применяются плюсы, заработанные тем же турнирным результатом.

## Double Strike

Default observed-конфигурации:

```text
Mode: A
Scope: newcomers_only
```

Режим A выполняет provisional-проход, пересчитывает KT, после чего финальный расчёт положительных изменений начинается от исходного предтурнирного состояния.

Scope `newcomers_only` означает, что второй расчёт применяется только при наличии в турнире нового игрока.

Эта настройка является частью observed-профиля и остаётся доступной для изменения в лаборатории.

## Новые игроки

Для нового игрока:

```text
initial_eu = 0
initial_marks = 0
initial_dan_date = empty
```

Его первое турнирное состояние определяется расчётом EU по результату участия.

## Временное понижение

Неактивность обрабатывается последовательной симуляцией турниров.

`initial_dan_date` используется как исходная дата последнего подтверждения данового состояния до начала загружаемой истории.

## Внешние игроки

`include_in_rating=false` исключает игрока только из отображаемой внутренней рейтинговой таблицы.

Такой игрок продолжает участвовать в турнирном расчёте и может влиять на KT и результаты остальных участников.

## Default-конфигурация

```text
rating = 0.25 × EU + 0.75 × T5
T5 = top 5
KT_EU rounding = floor to 0.05
Double Strike = A
Double Strike scope = newcomers_only
substitute EU = 0
kyu→dan = through D1, residual excess → pluses
dan confirmation = clear minus first, then add new pluses
successes per dan step = 2
dan step = 500
```

Методика остаётся исследовательской реконструкцией и может уточняться при появлении новых проверочных данных.
