# Mahjong Rating Lab

Интерактивная клиентская лаборатория для воспроизводимого расчёта, настройки и сравнения рейтинговых систем маджонга.

Проект вырос из **MCR Rating Lab** и сейчас поддерживает две полноценные методики:

- **MCR-2026** — восстановленная и формализованная модель российского рейтинга по спортивному маджонгу MCR;
- **RR** — внутренний российский рейтинг игроков в риичи.

Расчёты выполняются непосредственно в браузере. Загружаемые пользователем CSV-файлы не отправляются на сервер.

## Возможности

- расчёт `MCR-2026 default`;
- расчёт `RR default`;
- сравнение нескольких методик на одном dataset;
- независимая валидация данных для каждой методики;
- исторический срез рейтинга на выбранную дату;
- последовательная симуляция турниров;
- выбор двух методик для сравнения на исторической шкале;
- выбор произвольного временного диапазона;
- просмотр движения отдельного игрока;
- сравнение мест и рейтинговых значений после каждого турнира;
- интерактивные формулы MCR-2026 и RR в KaTeX;
- изменение коэффициентов и таблиц прямо из лаборатории;
- сохранение пользовательских presets для MCR-2026 и RR;
- сортировка рейтинговых таблиц;
- CSV-экспорт итогового сравнения и рейтинга после выбранного шага;
- встроенный полностью синтетический demo dataset;
- архитектура для последующего подключения дополнительных рейтинговых методов.

## Локальный запуск

Требуется современная версия Node.js.

```bash
npm ci
npm run dev
```

Production-сборка:

```bash
npm run build
```

Готовые статические файлы создаются в каталоге `dist/`.

# Сравнение методик + история

Основная вкладка приложения предназначена для исследования нескольких рейтинговых методик на одном и том же наборе данных.

Сейчас доступны:

- `MCR-2026 default`;
- `RR default`;
- пользовательские MCR presets;
- пользовательские RR presets.

Один и тот же набор `players.csv + results.csv` передаётся каждому движку независимо. Каждая методика сама определяет, какие турниры из набора допустимы для её расчёта.

Поэтому ошибка одной методики не блокирует остальные. Например, турнир с числом участников, которого нет в нормативной таблице `KT_ЧУТ`, может быть недопустим для канонического MCR-2026, но полностью корректен для RR.

## Верхняя таблица сравнения

Таблица показывает позиции игроков в выбранных методиках и позволяет оценивать различия между ними.

Для таблицы доступны:

- сортировка по колонкам;
- сравнение позиций;
- CSV-экспорт.

Абсолютные значения рейтинга MCR и RR не трактуются как напрямую сопоставимые числовые шкалы. Основной объект сравнения — место игрока и изменение места между методиками.

## История / симуляция

Турниры обрабатываются строго последовательно:

```text
Tournament 1
    ↓
state 1
    ↓
Tournament 2
    ↓
state 2
    ↓
...
```

Для каждого турнира создаётся исторический snapshot рейтинга.

На исторической шкале можно выбрать любые две доступные методики:

- `MCR-2026 default`;
- `RR default`;
- сохранённый MCR preset;
- сохранённый RR preset.

Карточка **«Методы»** позволяет заменить сравниваемую пару.

Карточка **«Период»** позволяет ограничить начало и конец отображаемой истории.

График движения игрока показывает две выбранные методики одновременно.

Таблица **«Рейтинг после этого шага»** сравнивает именно выбранные Метод 1 и Метод 2:

- место в Методе 1;
- место в Методе 2;
- рейтинг по Методике 1;
- рейтинг по Методике 2;
- `Δ Rating`;
- `Δ место`.

Для таблицы доступны сортировка по колонкам и отдельный CSV-экспорт.

# Лаборатория

Вкладка **«Лаборатория»** предназначена для подробного изучения и модификации рейтинговых моделей.

Пользователь сначала выбирает методику:

```text
MCR-2026
RR
```

После этого открываются её формула, пояснения, коэффициенты, таблицы и экспериментальные настройки.

Изменённую конфигурацию можно сохранить как пользовательский preset.

Presets:

- хранятся локально в браузере;
- не отправляются на сервер;
- не изменяют канонический `default`;
- доступны как отдельные методики на вкладке сравнения.

# MCR-2026

## Итоговый рейтинг

```text
Rating = 0.25 × EU + 0.75 × T5
```

где:

- `EU` — текущий эволюционный уровень игрока;
- `T5` — показатель пяти лучших турнирных результатов.

## Норморейтинг

```text
NR = 1000 × (ЧУТ - место) / (ЧУТ - 1)
```

Первое место получает `NR = 1000`, последнее — `NR = 0`.

## Коэффициент турнира

```text
KT = KT_ЧС + KT_ЧУТ + KT_EU + KT_W
```

где:

- `KT_ЧС` — коэффициент числа сессий;
- `KT_ЧУТ` — коэффициент числа участников;
- `KT_EU` — коэффициент состава турнира;
- `KT_W` — коэффициент статусного турнира.

### KT_ЧС

```text
KT_ЧС = sessions × 0.1
```

Коэффициент одной сессии можно изменять в лаборатории.

### KT_ЧУТ

В каноническом режиме `KT_ЧУТ` определяется строго по нормативной таблице.

Если значение ЧУТ отсутствует в таблице, `MCR-2026 default` не интерполирует его автоматически и помечает расчёт как неполный.

В лаборатории доступны дополнительные экспериментальные режимы обработки такого турнира:

- strict;
- ближайшее нижнее значение;
- ближайшее значение;
- линейная интерполяция;
- исключение турнира.

Только strict-режим относится к `MCR-2026 default`.

ЧУТ должен учитывать максимальное число игроков, включая игроков замены, одновременно участвующих в любой сессии турнира.

### KT_EU

В основе коэффициента состава турнира лежит средний EU участников на начало турнира:

```text
mean(EU) / 1000
```

В текущей реализации значение округляется вниз с шагом `0.05`.

Шаг округления и нормализатор доступны как экспериментальные параметры.

### KT_W

Для статусного турнира:

```text
KT_W = 1
```

Для обычного турнира:

```text
KT_W = 0
```

В лаборатории величину бонуса можно изменять.

## Изменение EU и ранга

Шкала кю/дан ↔ EU хранится как отдельный нормативный справочник.

Для игрока уровня 1 кю и ниже при выполнении условия

```text
EU_before <= NR × KT
```

присваивается ранг, соответствующий ближайшему снизу значению EU.

Для игрока уровня 1 дан и выше количество полученных плюсов определяется величиной превышения результата над текущим EU.

Плюсы и минусы взаимно уничтожаются.

Два накопленных плюса переводят игрока на следующий дан.

В лаборатории дополнительно можно включить ограничение:

```text
из кю максимум до 1 дана за один турнир
```

## Временное понижение

Для дановых игроков хранится дата последнего турнира, на котором было выполнено условие:

```text
EU_before <= NR × KT
```

Проверка временного понижения производится при последовательной обработке очередного турнира только для учитываемых в рейтинге игроков, которые не принимают участие в этом турнире.

Дата рейтинга является исторической границей расчёта: турниры после выбранной даты не существуют для симуляции.

## T5

Для каждого турнира вычисляется:

```text
NR × KT × VT
```

Из всех турниров игрока выбираются не более пяти результатов с максимальным значением этого произведения.

```text
T5 = Σ top-5(NR × KT × VT) / 5
```

Если у игрока сыграно меньше пяти турниров, сумма всё равно делится на 5.

## VT — устаревание результата

| Возраст | VT |
| --- | ---: |
| 0–2 мес. | 1.00 |
| 3–5 | 0.92 |
| 6–8 | 0.84 |
| 9–11 | 0.76 |
| 12–14 | 0.68 |
| 15–17 | 0.60 |
| 18–20 | 0.52 |
| 21–23 | 0.44 |
| 24–26 | 0.36 |
| 27–29 | 0.28 |
| 30–32 | 0.20 |
| 33–35 | 0.12 |
| 36+ | 0.00 |

Таблица может быть скопирована в экспериментальный режим и изменена без изменения нормативного справочника.

## Double Strike

Double Strike используется при появлении в турнире нового игрока с начальным `EU = 0`.

Интерфейс позволяет сравнивать три режима.

### Нет

Турнир рассчитывается один раз.

### A — полный пересчёт

Первая итерация используется для определения нового EU новичков.

После этого:

1. пересчитывается средний EU состава;
2. пересчитывается KT;
3. состояние всех игроков возвращается к состоянию до турнира;
4. турнир рассчитывается заново один раз с новым KT.

Первая итерация не создаёт отдельного слоя изменений рейтинга.

### B — продолжение первой итерации

Сначала выполняется обычный первый расчёт турнира.

После изменения EU участников:

1. пересчитывается средний EU;
2. пересчитывается KT;
3. выполняется вторая итерация уже от состояния после первой.

В этом варианте вторая итерация может добавить дополнительные изменения ранга.

Режимы A и B существуют для исследования двух возможных трактовок Double Strike.

## Игроки замены

Для расчёта `KT_EU` доступны три политики.

### EU = 0

EU игрока замены считается равным нулю.

### Среднее арифметическое

Вместо индивидуального EU игрока замены используется средний EU остальных участников турнира.

### Считать новичком

Игрок замены рассматривается как новый игрок.

Его EU на первой итерации принимается равным нулю, а дальнейшая обработка зависит от выбранного режима Double Strike.

## Внешние игроки

Игрок может участвовать в расчётах турниров, но не отображаться во внутреннем рейтинге.

Для этого используется признак:

```text
include_in_rating
```

Такие игроки сохраняют своё рейтинговое состояние между турнирами и могут влиять на `KT_EU`, если участвуют в турнире повторно.

# RR — внутренний рейтинг по риичи

RR использует турниры за последние два года.

В текущей реализации математическая часть RR перенесена на TypeScript и работает полностью в браузере.

Каждый элемент формулы RR интерактивен: по клику на обозначение или коэффициент открывается пояснение и связанные настройки.

## Итоговый рейтинг

Расчёт состоит из двух частей:

```text
RR = A × 0.5 + B × 0.5
```

Веса обеих частей доступны для изменения в лаборатории.

## Базовый ранг игрока

Базовый ранг результата находится в диапазоне от `0` до `1000`:

```text
R = ((N - p) / (N - 1)) × 1000
```

где:

- `N` — количество игроков турнира;
- `p` — место игрока.

Первое место получает `1000`, последнее — `0`.

В количестве игроков учитываются игроки замены.

## Турнирный коэффициент

```text
W = K_players + K_hanchans
```

### Количество ханчанов

Базовый коэффициент равен `0`.

По умолчанию:

| Ханчаны | Прибавка |
| --- | ---: |
| 1–8 | +0.20 за ханчан |
| 9–12 | +0.15 |
| 13–16 | +0.10 |
| 17–20 | +0.05 |
| 20+ | фиксированный коэффициент 2.8 |

Границы диапазонов и коэффициенты редактируются в лаборатории.

### Количество игроков

Базовый коэффициент равен `0`.

По умолчанию:

| Игроки | Прибавка |
| --- | ---: |
| первые 60 | +0.10 за каждых 4 игроков |
| 61–120 | +0.05 за каждых 4 игроков |
| 121–180 | +0.01 за каждых 4 игроков |
| 180+ | фиксированный коэффициент 2.4 |

Границы диапазонов и коэффициенты редактируются в лаборатории.

## Угасание результата

Турниры за последние 12 месяцев учитываются полностью.

После этого вес уменьшается каждые 2 месяца на `1/7`.

После двух лет результат имеет нулевой вес.

Параметры decay доступны для экспериментов в лаборатории.

## Первая часть

```text
A = Σ(W × R × Age) / Σ(W × Age)
```

Если игрок сыграл меньше пяти турниров, недостающие турниры добавляют `0` в числитель и `1` в знаменатель.

Если сыграно больше пяти турниров, учитываются:

```text
5 + ceil(0.8 × (T - 5))
```

лучших результатов.

Количество базовых турниров и коэффициент `0.8` доступны для изменения.

## Вторая часть

Используются четыре лучших результата игрока:

```text
B = Σ top-4(W × R × Age) / Σ top-4(MAXK)
```

`MAXK` — четыре максимальных коэффициента турниров среди всех подходящих турниров рейтингового периода с учётом устаревания.

Число учитываемых лучших турниров также можно менять в лаборатории.

## Турниры с отсечением

Для турниров с этапами коэффициент может быть различным для разных игроков.

Историческая реализация использует специальные коэффициенты для конкретных пар:

```text
tournament_id + player_id
```

Они перенесены из `HARDCODED_COEFFICIENTS` и доступны для просмотра и редактирования в лаборатории.

Текущая CSV-схема не содержит полной структуры этапов турнира, поэтому автоматическое восстановление индивидуального коэффициента по числу сыгранных этапов пока не выполняется.

## Требования к данным RR

Математические требования, которые можно проверить по CSV, валидируются самим RR-движком.

Для турниров начиная с 2018 года проверяются:

- минимум 16 игроков;
- минимум 4 ханчана.

Административные условия, например аккредитация или открытость турнира, не могут быть проверены без соответствующих полей в источнике данных.

Игрок отображается в рейтинге RR при наличии минимум двух турнирных результатов с ненулевым коэффициентом устаревания.

# Интерактивные формулы

Формулы MCR-2026 и RR выводятся через KaTeX.

Обозначения и коэффициенты в формуле интерактивны.

По клику открывается:

- объяснение параметра;
- его текущее значение;
- связанные коэффициенты;
- редактируемая таблица, если параметр задаётся диапазонами или справочником.

Таким образом формула используется одновременно как математическое описание и как навигация по лаборатории.

# Пользовательские presets

Изменённую конфигурацию MCR-2026 или RR можно сохранить как пользовательский preset.

Preset содержит настройки конкретного рейтингового движка.

Сохранённые presets:

- хранятся в `localStorage` браузера;
- не отправляются на сервер;
- не изменяют `default`;
- могут быть выбраны как отдельная методика на вкладке сравнения;
- могут сравниваться с MCR-2026, RR и другими сохранёнными presets.

# Формат данных

Приложение использует два основных файла:

```text
players.csv
results.csv
```

Формат общий для всех рейтинговых движков, но каждая методика самостоятельно валидирует подходящие ей турниры.

## players.csv

Базовый набор полей:

```text
player_id,player_name,initial_eu,initial_marks,initial_dan_date
```

Основные поля:

- `player_id` — уникальный идентификатор игрока;
- `player_name` — отображаемое имя;
- `initial_eu` — EU до начала загружаемой истории;
- `initial_marks` — накопленные плюсы/минусы;
- `initial_dan_date` — дата последнего турнира до начала истории, на котором было выполнено условие `EU_before <= NR × KT`.

Дополнительно может использоваться:

```text
include_in_rating
```

Если значение `false`, игрок участвует в расчётах турниров, но не отображается во внутренней рейтинговой таблице.

Для нового игрока MCR:

```text
initial_eu = 0
initial_marks = 0
initial_dan_date = empty
```

Дополнительные колонки допустимы.

## results.csv

Базовые поля:

```text
tournament_id,tournament_name,tournament_date,tournament_order,player_id,place,participants,sessions,is_status_tournament,is_substitute
```

Основные поля:

- `tournament_id` — идентификатор турнира;
- `tournament_name` — название турнира;
- `tournament_date` — дата турнира;
- `tournament_order` — порядок обработки турниров при совпадении даты;
- `player_id` — идентификатор игрока;
- `place` — итоговое место;
- `participants` — число участников / ЧУТ;
- `sessions` — число сессий / ханчанов;
- `is_status_tournament` — признак статусного турнира для MCR;
- `is_substitute` — признак игрока замены.

Для обратной совместимости старое поле `is_world_europe` временно принимается как alias для `is_status_tournament`.

Отсутствие MCR-специфичного поля само по себе не должно блокировать загрузку dataset для другой методики.

# Demo dataset

В репозитории находится полностью синтетический демонстрационный набор:

```text
public/data/players_demo.csv
public/data/results_demo.csv
```

Он моделирует многолетнюю турнирную историю и не содержит реальных персональных данных.

Demo dataset включает разные группы синтетических игроков, различную частоту участия, внутренние и внешние турниры и возвращающихся внешних игроков.

Реальные CSV пользователь загружает самостоятельно. Они обрабатываются только в браузере и не отправляются на сервер.

---

# Архитектура

```text
Data source
    ↓
normalized players / results
    ↓
method-specific validation
    ↓
┌─────────────────┬─────────────────┐
│ MCR-2026 engine │    RR engine    │
└─────────────────┴─────────────────┘
    ↓
ranking snapshots / history
    ↓
comparison / timeline / export
```

Основные модули:

```text
src/engine/legacy.ts
src/engine/evolution.ts
src/engine/rr.ts
src/engine/simulation.ts
src/engine/legacyTables.ts
src/ui/formulas.ts
```

Название файла `legacy.ts` пока сохранено по историческим причинам; содержащаяся в нём текущая реализация соответствует модели MCR-2026.

Архитектура рассчитана на последующее добавление новых рейтинговых движков без изменения общего формата данных и интерфейса сравнения.

# Статус проекта

Проект находится в стадии разработки и используется как вычислительный и исследовательский стенд.

Некоторые положения исходных рейтинговых описаний допускают несколько трактовок. В таких случаях приложение не скрывает допущение, а предоставляет явно выбираемые варианты расчёта.

`MCR-2026 default` и `RR default` используются как воспроизводимые базовые реализации для сравнения с пользовательскими экспериментальными конфигурациями.
