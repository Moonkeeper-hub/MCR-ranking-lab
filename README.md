# Mahjong Rating Lab

**Mahjong Rating Lab** — клиентский исследовательский стенд для воспроизводимого расчёта, настройки, сравнения и симуляции рейтинговых систем маджонга.

Проект вырос из **MCR Rating Lab**, но теперь поддерживает несколько независимых рейтинговых движков и собственный генератор синтетической турнирной истории.

Сейчас доступны четыре методики:

- **MCR-2026** — восстановленная и формализованная модель российского рейтинга по спортивному маджонгу MCR;
- **RR** — внутренний российский рейтинг игроков в риичи;
- **TrueSkill Tournament** — турнирная multiplayer-версия TrueSkill по полному порядку итоговых мест;
- **Elo-PL** — Elo-like рейтинг на основе полноценной модели Plackett–Luce.

Все расчёты выполняются непосредственно в браузере. Загружаемые CSV-файлы и синтетические datasets не отправляются на сервер.

## Возможности

- расчёт `MCR-2026 default`;
- расчёт `RR default`;
- расчёт `TrueSkill Tournament default`;
- расчёт `Elo-PL default`;
- независимая валидация данных для каждой методики;
- интерактивное изменение параметров формул;
- сохранение пользовательских presets;
- сравнение нескольких методик на одном dataset;
- выбор двух методик на исторической шкале;
- исторические snapshots после каждого турнира;
- просмотр траектории отдельного игрока;
- сравнение мест и рейтинговых значений;
- метрика дистанции;
- сравнительные гистограммы;
- CSV- и SVG-экспорт;
- client-side cache и Web Workers для тяжёлых расчётов;
- генератор synthetic `players.csv`;
- генератор tournament templates;
- воспроизводимая генерация многолетней истории по seed;
- симуляция турниров по отдельным турам;
- экспорт generated `players.csv`, `results.csv` и `manifest.json`.

```text
Сравнение методик + история
Лаборатория
```

## Сравнение методик + история

Основная вкладка предназначена для сравнения рейтингов на одном и том же dataset.
Можно использовать:

- `MCR-2026 default`;
- `RR default`;
- `TrueSkill Tournament default`;
- `Elo-PL default`;
- сохранённые пользовательские presets.

Каждая рейтинговая методика валидирует данные самостоятельно. Ошибка одной методики не блокирует остальные.
Например, турнир с числом участников, отсутствующим в нормативной таблице `KT_ЧУТ`, может быть непригоден для `MCR-2026 default`, но полностью корректен для RR, TrueSkill Tournament или Elo-PL.

### Верхняя таблица сравнения

Таблица позволяет сравнить итоговые позиции игроков по нескольким методикам.
Доступны:
- сортировка по колонкам;
- сравнение мест;
- сравнение рейтинговых значений;
- CSV-экспорт.
Абсолютные шкалы разных рейтингов не предполагаются напрямую сопоставимыми. Основной универсальный объект сравнения — порядок игроков и изменение места.

### Историческая шкала

Турниры обрабатываются последовательно:
```text
Tournament 1
    ↓
state 1
    ↓
Tournament 2
    ↓
state 2
    ↓
...
```

Для каждого шага создаётся snapshot рейтинга.
Карточка **«Методы»** позволяет выбрать любые две доступные методики.
Карточка **«Период»** позволяет ограничить начало и конец отображаемой истории.
График движения игрока показывает обе выбранные методики одновременно.
Таблица **«Рейтинг после этого шага»** содержит:
- место по Методике 1;
- место по Методике 2;
- rating по Методике 1;
- rating по Методике 2;
- `Δ Rating`;
- `Δ место`.

Для таблицы доступны сортировка и отдельный CSV-экспорт.

# Метрика дистанции

Метрика предназначена для сравнения того, насколько быстро и устойчиво рейтинговая методика выводит игрока на его лучшие позиции.
Для каждого игрока анализируется последовательность:
1. определяется лучшее место, достигнутое в начальном горизонте;
2. считается число сыгранных этим игроком турниров до повторного достижения того же или лучшего места;
3. при достижении более высокого места оно становится новой целью;
4. последний незавершённый участок до конца истории также включается.

Настраиваются:
- `Top-N`;
- шаг диапазона мест `1–10`.

Для каждой методики строятся две гистограммы:
```text
Σ турниров до места / число наблюдений
```
и
```text
Σ турниров до места / все зачётные турниры методики
```
Соответствующие графики разных методик используют одинаковую шкалу Y.

Доступны:
- CSV-экспорт агрегатов;
- SVG-экспорт пары графиков.

# Лаборатория

Вкладка **«Лаборатория»** предназначена для изучения и изменения параметров рейтинговых моделей.
Пользователь выбирает методику:
```text
MCR-2026
RR
TrueSkill Tournament
Elo-PL
```

После выбора отображаются:
- формула;
- пояснения параметров;
- коэффициенты;
- таблицы;
- экспериментальные controls.

Формулы выводятся через KaTeX. Обозначения и коэффициенты интерактивны: нажатие на элемент формулы открывает его описание и связанные настройки.
Изменённую конфигурацию можно сохранить как пользовательский preset.

Presets:
- хранятся в `localStorage`;
- не отправляются на сервер;
- не изменяют default-конфигурации;
- доступны на вкладке сравнения как отдельные методики.

# MCR-2026

## Итоговый рейтинг

```text
Rating = 0.25 × EU + 0.75 × T5
```
где:
- `EU` — текущий эволюционный уровень игрока;
- `T5` — показатель пяти лучших турнирных результатов.

## Норморейтинг

```text
NR = 1000 × (ЧУТ - место) / (ЧУТ - 1)
```
Первое место получает `NR = 1000`, последнее — `NR = 0`.

## Коэффициент турнира

```text
KT = KT_ЧС + KT_ЧУТ + KT_EU + KT_W
```
где:
- `KT_ЧС` — коэффициент числа сессий;
- `KT_ЧУТ` — коэффициент числа участников;
- `KT_EU` — коэффициент состава;
- `KT_W` — коэффициент статусного турнира.

### KT_ЧС

```text
KT_ЧС = sessions × 0.1
```
### KT_ЧУТ

В `MCR-2026 default` используется строгий lookup по нормативной таблице.
Если значение ЧУТ отсутствует в таблице, такой турнир не интерполируется автоматически и расчёт помечается как неполный.
В лаборатории доступны экспериментальные режимы:

- strict;
- ближайшее нижнее значение;
- ближайшее значение;
- линейная интерполяция;
- исключение турнира.
Только strict относится к default-модели.

### KT_EU

```text
mean(EU) / 1000
```
Значение округляется вниз с шагом `0.05`.

### KT_W
Для статусного турнира:
```text
KT_W = 1
```
для обычного:
```text
KT_W = 0
```

## EU и ранги

Для игрока 1 кю и ниже:
```text
EU_before <= NR × KT
```
приводит к присвоению ранга, соответствующего ближайшему снизу EU.
Для данового игрока превышение `NR × KT` над текущим EU преобразуется в плюсы.
Плюсы и минусы взаимно уничтожаются.
Два плюса переводят игрока на следующий дан.
Лаборатория позволяет ограничить продвижение из кю максимум первым даном за один турнир.

## Временное понижение

Проверка выполняется последовательно при обработке турниров для игроков, которые не участвуют в текущем событии.
Историческая дата расчёта является границей симуляции.

## T5

```text
T5 = Σ top-5(NR × KT × VT) / 5
```
Даже если результатов меньше пяти, деление выполняется на 5.

## VT

| Возраст | VT |
| --- | ---: |
| 0–2 мес. | 1.00 |
| 3–5 | 0.92 |
| 6–8 | 0.84 |
| 9–11 | 0.76 |
| 12–14 | 0.68 |
| 15–17 | 0.60 |
| 18–20 | 0.52 |
| 21–23 | 0.44 |
| 24–26 | 0.36 |
| 27–29 | 0.28 |
| 30–32 | 0.20 |
| 33–35 | 0.12 |
| 36+ | 0.00 |

## Double Strike

Поддерживаются:
- `Нет`;
- `A — полный пересчёт`;
- `B — продолжение первой итерации`.

## Игроки замены

Для `KT_EU` доступны политики:
- `EU = 0`;
- среднее арифметическое;
- считать новичком.

## Внешние игроки

`include_in_rating=false` означает, что игрок участвует в расчётах турниров и влияет на остальные рейтинговые значения, но не отображается во внутреннем рейтинге.

# RR — внутренний рейтинг по риичи
RR использует турниры за последние два года.

## Итоговый рейтинг
```text
RR = A × 0.5 + B × 0.5
```

## Базовый ранг
```text
R = ((N - p) / (N - 1)) × 1000
```
Первое место получает `1000`, последнее — `0`.

## Турнирный коэффициент
```text
W = K_players + K_hanchans
```

### Ханчаны

| Ханчаны | Прибавка |
| --- | ---: |
| 1–8 | +0.20 за ханчан |
| 9–12 | +0.15 |
| 13–16 | +0.10 |
| 17–20 | +0.05 |
| 20+ | фиксированно 2.8 |

### Игроки

| Игроки | Прибавка |
| --- | ---: |
| первые 60 | +0.10 за каждых 4 |
| 61–120 | +0.05 |
| 121–180 | +0.01 |
| 180+ | фиксированно 2.4 |

## Угасание
Последние 12 месяцев учитываются полностью. Затем вес уменьшается каждые 2 месяца на `1/7`.
После двух лет результат имеет нулевой вес.

## Первая часть

```text
A = Σ(W × R × Age) / Σ(W × Age)
```
Если сыграно меньше пяти турниров, недостающие результаты добавляют `0` в числитель и `1` в знаменатель.
Если сыграно больше пяти:
```text
5 + ceil(0.8 × (T - 5))
```
лучших результатов идут в зачёт.

## Вторая часть

```text
B = Σ top-4(W × R × Age) / Σ top-4(MAXK)
```
`MAXK` — четыре максимальных коэффициента турниров за рейтинговый период с учётом устаревания.

## Турниры с отсечением

Исторические специальные коэффициенты перенесены из `HARDCODED_COEFFICIENTS` и задаются для пары:
```text
tournament_id + player_id
```
Они доступны для просмотра и редактирования в лаборатории.

# TrueSkill Tournament

TrueSkill Tournament рассматривает весь турнир как одно multiplayer-наблюдение по полному порядку итоговых мест.
Ничьи в текущей модели турниров не предполагаются.

## Состояние игрока

Каждый игрок имеет:
```text
μ
σ
```

По умолчанию используются канонические значения TrueSkill:
```text
μ0 = 25
σ0 = 25 / 3
β = 25 / 6
```

Ранжирование выполняется по conservative score:
```text
score = μ - kσ
```
где по умолчанию:
```text
k = 3
```
Все базовые параметры имеют редактируемые коэффициенты.

## Календарный τ / decay

Между турнирами неопределённость игрока увеличивается:
```text
σprior = sqrt(σ² + τ² × Δt_years)
```
Множитель decay задаётся от `0` до `3`.

- `0` — календарное устаревание выключено;
- `1` — default;
- `3` — усиленное устаревание.

## Турнирная поправка

После чистого TrueSkill update применяется вес турнира:
```text
μ' = μ + wT(μTS - μ)
σ' = σ + wT(σTS - σ)
```
В `wT` отдельно учитываются:
- размер турнира;
- число туров / ханчанов.
Общий коэффициент турнирной поправки равен `0` — поправка выключена.

# Elo-PL
Elo-PL использует полноценную модель Plackett–Luce для полного порядка игроков.
Стартовый рейтинг:
```text
1500
```
Вероятность порядка:
```text
P(π) =
∏ exp(rπi / s)
  ─────────────
  Σ exp(rπj / s)
```
Изменение рейтинга определяется градиентом log-likelihood:
```text
r' = r + Keff × ∂logP / ∂r
```

## Редактируемые параметры
В лаборатории доступны:
- Base K;
- PL scale / temperature;
- влияние размера турнира;
- влияние опыта игрока;
- влияние числа туров;
- параметры experience decay;
- minimum players.

## Нормализация
Можно выбрать:
```text
Off
0–1000
0–3000
```
Нормализация меняет только отображаемое значение. Внутреннее Elo-PL состояние всегда остаётся на исходной шкале.

# Mock generator

Вкладка **Mock generator** создаёт воспроизводимые synthetic datasets для тестирования рейтинговых систем.
Генератор разделён на:
```text
Players
Tournament templates
History generation
```

## Генератор игроков
Каждый player template содержит параметры, которые используются только симулятором истории.
Основные поля:
- имя;
- `latent_elo`;
- activity;
- external activity;
- consistency;
- `skill_drift_per_year`;
- `active_from`;
- `active_to`;
- `include_in_rating`;
- страна / профиль;
- initial MCR state;
- multiplier.

### latent ELO
`latent_elo` — скрытая истинная сила игрока. Она используется только генератором результатов и не передаётся рейтинговым методикам как известное значение.

### Activity
`activity` задаёт вероятность участия игрока во внутренних турнирах.
`external_activity` используется для внешних событий.

### Consistency
Consistency управляет разбросом performance относительно `latent_elo`. Высокая стабильность означает меньшую случайную дисперсию.

### Skill drift
Текущая скрытая сила игрока изменяется со временем:
```text
effective_elo =
latent_elo +
skill_drift_per_year × years_since_active_from
```

### Active period

Игрок может участвовать только если дата турнира находится между:
```text
active_from
active_to
```
После `active_to` он не исчезает из generated `players.csv` и исторических рейтингов — он только перестаёт участвовать в новых турнирах.

### include_in_rating
`false` используется, например, для внешних игроков — «уток».
Они участвуют в турнирах и влияют на расчёт рейтингов, но не входят во внутреннюю итоговую таблицу.

### Multiplier

Один шаблон может создать сразу несколько игроков.
При необходимости к базовому имени автоматически добавляются характеристики силы, активности, стабильности и типа игрока.

Tournament template задаёт повторяющийся тип соревнования.

- число substitutes;

## Рассадка

Доступны:
### Random
Каждый тур состав столов формируется случайно.

### Swiss
Игроки группируются по текущему tournament standing.

### Seeded → Swiss
Первый тур использует первоначальный посев по synthetic strength, следующие — Swiss.

# Квотный отбор
Статусный турнир может резервировать часть мест для игроков, выбранных по рейтингу.
Можно выбрать:
```text
Neutral mock rating
MCR-2026 default
RR default
TrueSkill Tournament default
Elo-PL default
```

## Neutral mock rating

Neutral mock rating используется, когда генерация не должна зависеть от одной из исследуемых рейтинговых систем.
Для каждого результата:

```text
result_score =
1000 × (N - place) / (N - 1)
```
Mock-рейтинг обновляется:
```text
MockRating_new =
(1 - α) × MockRating_old
+ α × result_score
```
По умолчанию:

```text
α = 0.25
```
Этот рейтинг используется только для synthetic qualification и не является отдельной исследуемой методикой.

---

# External tournaments

Внешние турниры используют специальный порядок формирования состава.

1. Сначала резервируются substitutes.
2. Игроки `include_in_rating=true` допускаются только через рейтинговую квоту.
3. Остальные регулярные места заполняются игроками `include_in_rating=false`.
4. Если внешних игроков недостаточно, оставшиеся места заполняются одноразовыми substitutes.
Таким образом внутренние игроки не могут заполнить весь внешний турнир только за счёт высокой activity.

# Симуляция истории
Кнопка **Generate history** становится доступна после создания пула игроков и стека tournament templates.
Глобально задаются:
```text
Seed
History start
History end
```
Одинаковые:
```text
seed
player templates
tournament templates
period
generator settings
```
должны давать одинаковый dataset.

## Pipeline

```text
Player templates
    ↓
expand players
    ↓
Tournament templates
    ↓
expand calendar
    ↓
for each tournament:
    eligible players
    ↓
reserve substitutes
    ↓
rating quota
    ↓
fill remaining seats
    ↓
simulate rounds
    ↓
final places
    ↓
update Neutral mock rating
```

## Симуляция результата

Для каждого игрока вычисляется текущий synthetic skill:
```text
effective_elo =
latent_elo +
drift × years_since_active_from
```
На каждом туре генерируется performance, зависящий от:
- effective ELO;
- consistency;
- tournament skill influence;
- tournament randomness.

По результатам каждого стола начисляются tournament points:
```text
1 место → 4
2 место → 2
3 место → 1
4 место → 0
```
Итоговый `place` определяется по:
1. сумме tournament points;
2. суммарному raw performance;
3. среднему месту за столами;
4. deterministic seeded tie-break.

```text
manifest.json
```
После генерации доступны:
```text
Use in Rating Lab
Download players.csv
Download results.csv
Download manifest.json
```

`Use in Rating Lab` сразу передаёт synthetic dataset в основной рейтинговый pipeline.

`manifest.json` хранит:
- seed;
- диапазон дат;
- player templates;
- tournament templates;
- глобальные параметры генерации;
- число созданных и отменённых турниров;
- число substitutes.

# Формат данных

## players.csv

Базовые рейтинговые поля:

```text
player_id,
player_name,
initial_eu,
initial_marks,
initial_dan_date,
include_in_rating
```

Mock generator дополнительно использует simulation-only поля:

```text
latent_elo,
activity,
external_activity,
consistency,
skill_drift_per_year,
active_from,
active_to,
country
```

Рейтинговые движки игнорируют simulation-only поля.

## results.csv

Основные поля:

```text
tournament_id,
tournament_name,
tournament_date,
tournament_order,
player_id,
place,
participants,
sessions,
is_status_tournament,
is_substitute
```

Дополнительные колонки допустимы.

Для обратной совместимости `is_world_europe` временно может приниматься как alias `is_status_tournament`.

# Статус проекта

Проект находится в стадии разработки и используется как вычислительный и исследовательский стенд.

Он предназначен для:
- воспроизведения существующих рейтингов;
- исследования чувствительности формул к параметрам;
- сравнения различных методов на одинаковой истории;
- генерации контролируемых synthetic datasets с известной скрытой силой игроков;
- проверки того, насколько разные рейтинги восстанавливают и удерживают порядок игроков;
- подготовки и проверки предложений по изменению рейтинговых систем.

Некоторые положения исходных рейтинговых описаний допускают несколько трактовок. В таких случаях приложение стремится не скрывать допущение, а делать его явно выбираемым параметром.
`MCR-2026 default`, `RR default`, `TrueSkill Tournament default` и `Elo-PL default` используются как базовые воспроизводимые реализации для сравнения с пользовательскими экспериментальными конфигурациями.
